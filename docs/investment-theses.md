# 登録記事から投資論点を抽出する

## 目的と画面

フッターの「投資論点」から専用画面を開く。登録済み記事を横断して、反証可能な仮説を最大10本提示する。各論点は仮説、利益への影響経路、恩恵候補、逆風、反証条件、確認指標、時間軸、根拠記事・段落を持つ。根拠を開くと取得範囲の原文、記事へのリンク、原典へのリンクを表示する。

AI提案は本人の見解として自動採用しない。「AIで論点を抽出」→対象件数と外部送信・API予算の説明→「はい、実行する」でのみPOSTする。閲覧・画面更新ではAIを呼ばない。10本は目標であり、材料不足なら0〜9本を許容する。

## 対象と選定

抽出が成功した実行に供給した記事は、その版（revision）を使用済みとして記録し、次回の対象から除外する。論点の根拠として引用されなかった記事や、結果が0本だった場合も、分析は済んでいるため使用済みとなる。API失敗・予算不足・出力検証失敗では使用済みにしない。新しい版は再び対象となる。使用済みIDは論点出力と同じD1バッチで保存し、記事削除後も原文を含まないIDだけ保持する。0010のmigrationは既存の成功履歴を取り込む。

現在の版があり、非表示・削除されていない記事のうち、原文リンクだけでない取得範囲、原文段落、保存・AI処理許可、既存の媒体ポリシー確認を通るものを対象にする。`loadCapture`の既存チェックを再利用する。本文未取得・許可なしの記事は件数を明示して除外する。要約は要約の取得範囲として扱い、全文の根拠と誤認させない。

v1は現在の版の作成順で最大100記事を走査し、最大30記事・入力資料48KBまで、記事の取得範囲単位で選ぶ。切り詰めはしない。全登録記事を網羅する機能ではない。長い記事が入らない場合や100件を超えるコーパスでは、将来の分割抽出と横断統合が必要。このPRはボタンによる一回の有限な抽出を提供する。

## 抽出と根拠検証

設定済みモデルのResponses APIにJSON Schemaで最大10本を要求する。供給した記事以外の検索・企業知識・銘柄・数値を追加しない。すべての資料を指示ではなく非信頼データとして扱う。似た仮説は統合し、共通語だけから因果を作らない。事実・企業発表・推論、転載と独立検証を区別する。根拠は原資料のrevisionとparagraphIdで固定する。

保存前に件数・構造・根拠IDの存在・完全一致する仮説の重複を検証する。意味上の妥当性や類似論点の完全な重複排除をコードだけで保証するものではない。実モデルでの品質評価は未実施。

## APIと永続化

- GET `/api/investment`：対象件数、AI設定可否、最新実行状態、現在も有効な結果と根拠を返す。
- POST `/api/investment`：`{confirmed:true,requestId:UUID}`。実行IDを返す。同じrequestIdは送信を繰り返さない。
- `0009_investment_theses.sql`：既存jobsの実行IDに紐づくinvestment_runs。スナップショットはslug/revisionのみ。原文の複製は保存しない。

既存Access認証、同一オリジンJSON制約、AI設定、日次/月次予算、同時実行上限を再利用する。予約は入力ペイロードのUTF-8バイト数による保守的な入力トークン見積もりと最大6000出力トークンから計算。実使用量を課金計上し、出力検証失敗も費用を残す。

v1はPOSTの中で最大120秒待つ。切断・タイムアウトの送信成否不明は予約を保持し、自動再送しない。画面を再度開けば記録された状態を確認できる。ブラウザ切断で処理継続を保証するものではなく、長時間・大量処理は将来専用Workflowへ移す。通常の翻訳ジョブ再試行からこの実行を誤って翻訳しないように拒否する。

元記事の更新・非表示・削除、媒体ポリシー変更、AI許可撤回で結果を表示しない。保存時に全記事の現在版をD1の同一バッチ内でチェックする。記事削除時はその記事を使った論点出力を消し、送信済みの費用は保持する。遅れて届いた結果による記事復活は起こさない。

## 検証とリリース

型検査、単体・SQLite実行テスト、既存統合テストで検証する。確認なし・AIオフ・予算不足で未送信、同じ実行IDの再送防止、捏造根拠の拒否、送信不明の予約保持、検証失敗の費用保持、記事削除後の結果除去をテストする。

PRは未マージの基盤PR #15のブランチをベースにする。マージ・本番デプロイはこの依頼の対象外。本番適用時は先に0009と0010のmigrationを適用する。モデル・キー・AI予算が未設定なら画面は閲覧できるが抽出は実行できない。
